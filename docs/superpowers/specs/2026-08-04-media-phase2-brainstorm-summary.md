## 一、本轮目标

验证外部 skill `ip-strategist` 是否可用、是否契合 AI-PM 设计理念；把它和用户 v3 失败复盘一起，融进自媒体二期设计；决定两者的整合关系。

## 二、验证结果（逻辑层面）

用**用户 4 条真实口播文案**当声音+素材样本，用 ip-strategist 方法论走「诊→契→行」，为选题「AI 如何真实落地到企业中」出新口播，做了两轮测试：

- **第一轮**（选题：30 天验证 AI 落地）→ 用户判断「像，是真的像」。
- **第二轮**（选题：中小企业 30 天试点）→ 用户判断仍像；且验证它**没把上一条换壳重写**（躲开了「套路复制」反模式）。

**验证通过项（纯文本、现在就能验）：**
- ✅ 声音：4 条样本就"真的像"
- ✅ 不编造：全程只用用户真料，守住 v3 断点一红线
- ✅ 流程产物（契约/证据包/角度）有实际价值
- ✅ 理念对齐：诊契行盘=v3双闭环；判断>执行、认知沉淀≥3次、创作/审稿分离=v3原则；与一期人拍板闸、media_case/replicable 咬合

**用户发现的唯一不足 = 文案「结构」偏模板**（两条都用了"三件事"列举体）。根因：**声音少量样本可学，结构曲库需语料库才能学**。4 条只够学声音，不够学结构repertoire → 退回安全模板。→ 直接推出二期核心需求（见 §五.7）。

**结论：ip-strategist 可用、高度契合。整合走「走法 C」（见 §三）。**

## 三、整合关系：走法 C（已定）

三者强弱互补：
- **ip-strategist 强在「判断方法论」**（12 个方法论文件是耳总实战经验），弱在持久化。
- **AI-PM 强在「状态/数据/持久化/多项目/验证」**——正是 v3 复盘说旧系统缺的四层。

**走法 C 的精确接缝（地基，就这一句）：**
> **AI-PM 数据库 = 唯一事实源**（状态/契约/证据包/人格档/benchmark 全在这）；**ip-strategist = 判断方法论 + 流程蓝图**（诊契行盘、契约字段、状态设计，指导 AI-PM 的表和流程，也可当 AI 出判断时读的方法论）。它的 dossier 四区（底座/契约索引/数据快照/认知沉淀）**映射成 AI-PM 的表**，不另存 markdown。

- 否 A（全吸收/重写方法论）：砸碎成熟资产重造，v3 明说判断最难别乱重建。
- 否纯 B（AI-PM 只当调用方）：ip 自己的 markdown 想当事实源 → 两个事实源 = v3 点名的 active-status 过期老毛病。

## 四、二期重整后的结构（拆成 5 块）

原二期只是 6 张表；吸收 v3 + ip-strategist 后变大，是「多子系统」，必须一块块来：

```
重整后的二期
├── 🅐 单条生产闭环升级 ← 证据包 + 角度候选 + 独立审稿 + 契约   ← 【先做】
├── 🅑 资产层 ← 原料库/打法库/教训/红线（原二期，靠人输入，不依赖数据）
├── 🅒 学习闭环升级 ← 契约核账 + 知识 candidate→approved 生命周期 + 数据回流
├── 🅓 验证层 ← benchmark 历史案例 + 盲评（证明新>旧）
└── 🅔 受众/锚点 ← 受众画像假设 + 生意锚点（原二期）
```

**先做 🅐**：不依赖数据、最高杠杆（就是刚验过的那套）、产物立刻能用；🅓🅒 靠数据的部分设计进去、随真实使用激活。

## 五、关键设计原则（从三方汇聚，动手时必须遵守）

1. **判断 > 执行**。方法论会被工具商品化，判断不能自动化。（ip 心法1 / v3）
2. **⭐ 契约（下注-验证）**：发布前先"签契约"——赌受众什么需求、赢面多大、发布后采什么数据验证。复盘对账，赌对没赌对**可证伪**。（原设计没有，本轮新增，是 v3 断点四的解）
3. **⭐ 证据包（真料先行）**：写稿前先攒本次专属真实素材包，**没真料不许编"本人经历"填结构**。（v3 断点一）
4. **⭐⭐ 创作器 ≠ 审稿器，禁止同一 agent 自写自评自打分**（用户本轮强调的硬铁律）：
   - 生产、审稿、打分**用不同的 AI 调用/agent**，不能一个模型自己写完自己给自己打高分（v3 断点二：同模型自评会越来越符合评分表，却不一定越来越真越有效）。
   - 审稿器只**指出**文本证据/风险/缺口，**修订由单独步骤**做（ip / v3 原则五）。
   - 落到 AI-PM：写脚本、独立审稿、打分 = 分开的服务/agent，互相不兜底自证。
5. **知识生命周期 candidate → approved → deprecated + 人拍板**：新观察≠规则，需≥3 次跨样本验证才沉淀；AI 提炼、人批准才生效。（一期已有雏形 trait status/confidence + 人拍板闸；本轮升级为更严生命周期 + registry 唯一事实源）
6. **生产闭环 与 学习闭环 分离**：生产闭环不能自行改人格；学习闭环不能未批准直接发布。（v3 原则四）
7. **⭐ 结构曲库从真实语料提取，不套模板**：喂真实历史文案 → 提炼用户**真实的骨架 repertoire**（=原设计"打法库/pattern_cards"）→ 按选题匹配结构，不再每条"三件事"。声音少样本可学，**结构需语料库**。
8. **⭐ 语料分类做对比验证**（用户本轮设计的实验方法，让"从爆款学习"科学而非幻觉）：
   - **全部语料** → 学声音基准（爆不爆都是有效样本）
   - **同话题：爆 vs 不爆** → 归因**表达/结构/钩子**（控制了选题天花板，最干净的因果信号）
   - **不同话题：爆** → 归因**选题**（哪些方向天花板高）
   - **不爆** → 失败模式（反面样本，没它无法判断成功要素是否成功独有）
   - 三个前提（否则自欺）：①得有同话题"成对样本" ②文案对比只锁"文案层"，平台/时机锁不住，真验证靠前瞻（用这结构再发几条看命中率）③"爆"要相对自己账号中位数（=一期 media_case.threshold_basis）
   - 这套正好接一期：同话题对比=诚实填 replicable；同话题反复出现的结构=打法库已验证 pattern；不爆失败模式=media_lesson；整套=v3 benchmark 验证层
9. **一个场景先跑通再扩展**：第一期只做**嘉姐视角短视频口播原创**（v3 §十二：使用频率高、人格资产最全、边界清楚、易建历史测试集），证明明显优于旧系统（v3 目标盲评胜率≥70%）再复制到公众号/仿写/图片/发布。
10. **每条规则必须可落地**：`触发条件→必需输入→执行动作→结构化产物→验收条件→失败处理→数据回流`；只能回答"系统应该怎样"、答不出"在哪步执行/留什么产物/怎么回流"的，先不加。（v3 原则一 + §十五）

## 六、从旧系统继承的资产（v3 §四，A 级核心基因）

- `values.md`：真实实践/反AI焦虑营销/反大师姿态/平视/长期主义/人与AI边界
- `DNA-Gaga.md`：身份错位禁忌/人称视角/自嘲自省有锋不高高在上/AI味卖课味焦虑词警报/真实不过度包装
- `fact-check-protocol.md`：数字引用研究产品能力必核验，无法验证则删/降/求来源，不编造本人经历和第三方证据
- `learning-protocol.md` + `content-addition-protocol.md`：观察≠规则、一次反馈不能升级DNA、外部爆款只学机制不污染人格、AI自己满意的句子不自动进金句库
- `ICP-canvas.md`：痛点分层法，但画像**只能当待验证假设**，不能当既定事实
- 写作零件：证据类型/判断与解释区分/结构原型/钩子原型/本人真实原话样本

## 七、双闭环（v3 §九，融合 ip 诊契行盘）

**单条内容生产闭环：**
```
任务简报 → 真实素材证据包 → 2-3角度候选 → 选角度 → 初稿
→ 事实/人格/平台硬审校 → 独立质量评审 → 必要时一次定向修订
→ 人工发布确认 → 平台包装与发布
```
（对应状态：brief_ready→evidence_ready→angles_ready→angle_selected→draft_ready→quality_checked→approved→published→measured→learned）

**跨内容学习闭环：**
```
发布结果 → 指标+高质量评论采集 → 与内容特征关联 → observation
→ 跨样本验证 → candidate → 人工批准 → 更新registry/pattern card → 回归测试 → approved
```

**默认只做一次定向修订**：第二次仍不好，优先回素材或角度，不继续润色措辞。（v3 原则六）
**两个强制人工确认点**：①涉及本人立场/真实经历边界/商业植入 ②正式发布前。其余低风险按合理默认继续。（v3 原则七）

## 八、现在能验证 / 不能验证（诚实边界）

| 要验的 | 现在能验吗 | 说明 |
|---|---|---|
| 像不像你（声音） | ✅ 已验 | 纯文本 |
| 结构丰不丰富（曲库） | ✅ 能 | 从历史文案文本提取，不需数据 |
| 流程产物有没有用 | ✅ 能 | 人看了有感觉 |
| 命中率高不高 | ❌ 不能 | 要真发内容攒数据 |
| 爆款归因准 / benchmark 盲评胜率 | ❌ 不能 | 要真实播放/点赞数据 |

**验证不了的那半 = 要设计的验证层🅓 本身，靠真实使用日后上线，不是设计前的前提。** 设计先行，数据验证随用出来。

# 建造师学习模块 B1（核心学习循环）· 设计文档

- **日期**：2026-06-24
- **载体**：集成进 ai-pm（FastAPI + Jinja2 + aiosqlite），作为独立「学习」模块
- **数据来源**：Phase A 资料处理引擎产出的四科 JSON（`D:\GAGA-5-25\建造师学习工具\data\output\`）
- **考试日**：2026-09-12｜**冲刺起点**：2026-08-15

## 1. 背景与目标

用户备考一建（四科：建筑实务/管理/法规/经济），每天可投入 **2–3 小时**，**手机使用远多于电脑**。Phase A 已产出四科结构化学习材料（3037 考点 + 122 精炼母题 + 四科 2026 预测密卷）。B1 把这些数据搬进 ai-pm，做成一个**主动驱动学习的循环**：每天告诉用户学什么、记录对错、按 1-3-7 安排复习，形成"学习智能体"的自主循环。

B 阶段分两层（已与用户确认）：
- **B1（本 spec）**：核心学习循环——导入、每日计划、考点自评、母题/密卷练习、1-3-7 复习调度、进度/倒计时、漏任务顺延。做完即可每天在 ai-pm 上学。
- **B2（后续，独立 spec）**：企业微信机器人提醒（强力轰炸+请假/顺延）、实务案例采分点 AI 评分、错题智能加权、母题变体强化。

## 2. 集成方式（路线 1：ai-pm 内独立模块）

不碰 ai-pm 现有 projects/notes/tasks 模块。新增：
- `app/api/study.py`：学习模块路由，main.py 加 `app.include_router(study.router)`
- `app/services/study_engine.py`：每日计划生成 + 1-3-7 复习调度核心逻辑
- `app/services/study_import.py`：一次性导入（读 Phase A JSON → 写 study_ 表，可重跑覆盖）
- `app/templates/study_*.html`：学习页面（手机优先，复用 ai-pm 现有 Dieter Rams 响应式样式系统）
- `app/database.py` 的 `SCHEMA` 追加 7 张 `study_` 表
- `base.html` 导航加「📚 学习」入口

**JSON 来源**：把 Phase A 的 `data/output/*.json` 拷到 ai-pm 的 `data/study_source/`（让 ai-pm 自包含，便于部署到服务器）。导入脚本从该目录读。

**数据流**：
```
Phase A 产出 JSON → study_import 导入 → ai-pm SQLite(study_ 表)
   → study_engine 每日生成计划+调度复习 → 学习页面(看/练/复习)
   → 记录对错&自评回写 study_review/study_records → 驱动次日计划
```

## 3. 数据模型（7 张 study_ 表，沿用 ai-pm 风格：TEXT 主键、created_at/updated_at）

### 内容表（导入 Phase A，只读）
- **study_points**：id, subject, chapter, title, content, type(JSON), importance(INT), memory_method, related(JSON), source_refs(JSON)
- **study_archetypes**：id, subject, stem, solution_logic, knowledge_points(JSON), variants(JSON)
- **study_questions**：id, subject, source, qtype(单选/多选/案例), stem, options(JSON), answer, maps_to(JSON)

### 学习状态表（核心）
- **study_review**（1-3-7 状态，每个学过的考点 + 每道错题一行）：
  id, item_type(point/question), item_id, subject, stage(INT：0→1→3→7→15→30 档位索引), due_date(DATE), last_result, updated_at
- **study_records**（行为流水，审计+统计）：id, item_type, item_id, subject, action(会/模糊/不会/对/错), plan_date, created_at
- **study_plan**（每日计划）：id, plan_date(DATE), items(JSON：[{item_type, item_id, kind:new/review}]), status(active/done), generated_at

### 配置表
- **study_settings**（单行）：daily_minutes(默认 150), rest_weekday(INT 0-6), subject_weights(JSON：实务0.32/管理0.32/法规0.20/经济0.16), exam_date(2026-09-12), sprint_date(2026-08-15), daily_new_target(默认 20)

**说明**：掌握度由 study_review.stage 反映；今日进度 = study_plan.items 完成比例（对照 study_records）。1-3-7 全部状态压在 study_review 一张表。

## 4. 每日计划 + 复习调度算法（study_engine）

### 生成今日计划（用户当天首次访问学习页时触发，幂等：当天已生成则复用）
1. **排到期复习**（最高优先）：study_review 中 due_date ≤ 今天的项 → 全进"复习"区。
2. **排新学**：按 subject_weights 分配今日新学名额（daily_new_target × 占比），每科按 importance 降序取未学考点 → "新学"区；每个新学考点附带其关联母题（study_archetypes 中 knowledge_points 命中者）。
3. **配额随复习量收缩**：复习项多的日子，新学名额相应减少（总量贴合 2–3 小时），避免堆爆。
4. **休息日**（rest_weekday）：不排新学，仅保留自愿复习。
5. **漏任务顺延**：昨日未完成项次日自动并入（复习顺延、新学回队列前部），不堆积。

### 1-3-7 调度（用户对某项操作后即时更新 study_review）
- 考点自评**会** / 题目**答对** → stage 进一档（0→1→3→7→15→30），due_date = 今天 + 该档天数。
- 自评**模糊/不会** / **答错** → stage 重置为 1，due_date = 明天。
- 新学考点首次自评"会"即进入 study_review（stage=1）；错题首次答错即进入。

### 倒计时自适应
离 exam_date 越近，新学名额自动缩、复习+刷题名额扩；过 sprint_date(8/15) 后基本停新学，全力刷高频考点+密卷+复习。

## 5. 页面（手机优先，复用 ai-pm 响应式样式；单列、大按钮、底部固定操作条）

1. **今日学习**（`GET /study`，主页）：顶部考试倒计时 + 今日进度条 + 四科掌握度；下方①复习区②新学区卡片列表。
2. **考点页**（`GET /study/point/{id}`）：标题/正文/记忆法/关联；底部 **会/模糊/不会** → 写 study_review，跳下一项。
3. **母题练习页**（`GET /study/archetype/{id}`）：题干+解题逻辑+逐个变体；底部 **会/不会**。
4. **密卷答题页**（`GET /study/exam/{subject}`）：单选/多选点选→提交自动判分；案例题显示标准答案供自评对照（AI 评分留 B2）；记对错。
5. **复习页**（`GET /study/review`）：study_review 到期项，快速过 + 会/不会。

操作回写接口（`POST /study/record`）：接收 {item_type, item_id, action}，更新 study_review + 写 study_records + 更新当日 study_plan 项状态。

## 6. 范围边界

**B1 做**：导入、每日计划、考点自评、母题练习、密卷自动判分、1-3-7 复习调度、进度/倒计时、漏任务顺延。
**B1 不做（留 B2）**：企业微信提醒、实务案例 AI 采分点评分、错题智能加权、母题变体自动生成强化。

## 7. 测试

- **study_engine 单元测试**：给定 study_review 状态 → 断言调度结果（会/对 → stage+1 与正确 due_date；模糊/不会/错 → stage 重置 due=明天）；配额按 subject_weights 分配；复习量大时新学收缩；漏任务次日并入；休息日不排新学；倒计时临近时新学缩减。
- **study_import 测试**：对四科 JSON 导入后断言各表条数与源 JSON 一致、字段映射正确。
- **页面**：手动验（手机视口为主）。

## 8. 验收标准

1. 导入后 study_points/archetypes/questions 条数与 Phase A 四科 JSON 一致。
2. 打开 /study 能看到当日计划（复习区+新学区）、倒计时、进度、四科掌握度。
3. 考点会/模糊/不会、母题会/不会、密卷答题判分均能正确回写并影响次日计划与复习队列。
4. 1-3-7 调度按算法正确推进/重置 due_date。
5. 所有页面在手机视口下单列、可操作、与 ai-pm 现有响应式风格一致。
6. study_engine 单元测试全绿。

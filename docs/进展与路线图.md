## 2026-08-14 · 自媒体二期「飞轮」大推进

这一天把自媒体模块从"能记录"推进到"能沉淀 + 能复用 + 多人设"。按上线顺序：

### 1. 老文案炼化 + 打法库🅐（merge `e0fbf25`）
- 老文案批量导入（粘文本→按序号切→预览确认→建成"已发/反向"内容 `media_content`，`idea_source=legacy_text`）。
- 挖精华加第三桶「结构/打法」（**仅爆款**）→ 新建**打法库** `media_playbook`。
- `is_winner` 标爆款（批量勾选）；采纳时 `similar_to` 归并/新建。
- **本轮零下游注入**：打法库只"装着"，先不碰写稿/决策。

### 2. 自媒体多人设总览 + 工作区隔离（merge `4996ac9`）
- `/media` 变**人设总览页**（每人设一张卡：定位/阶段/内容数/账号 + ➕新建），点进各自独立工作区，**cookie 记住当前人设**。
- 一份代码、一套功能——更新任何功能所有人设自动生效，**永不需要每人设一套系统**。
- **共享 vs 独享**（定了）：
  - **打法库 = 全公司共享**（可迁移方法论，一池子）。
  - **原料库 = 独享，但留了 `scope` 接口**（现纯隔离，将来一键开"公司级共享"）。
  - 其余（人设特征/账号/选题/内容/受众/锚点/复盘）= 独享。
- 底层地基早就是 `persona_id` 隔离，这轮只补了"选当前人设"的 cookie 层 + 总览页。

### 3. 自媒体模块 UI 重做（merge `f29ebf9`）
- 统一壳组件 `_media_shell.html`（体系库卡片 + 步骤条 + 面包屑），各页接壳。

### 4. 打法库🅓 接写稿（merge `bea0504`）
- 写口播脚本时，AI 从共享打法库挑**最贴选题的一条**打法当骨架注入。
- **注意力纪律**（最高优先级）：整个打法库只在**独立的 `match_playbook` 调用**里出现一次；写稿 prompt **只注匹配到的那一条**，匹配不到就零注入。
- 透明可测：写完显示"本次用了《X》· 理由"，可【换一条】/【不用打法重写】（现成 A/B 对比）。

### 5. 老文案批量挖矿 · 两条流（merge `1a129b4`）
- **流A · 批量挖记忆点**（口头禅→人设 signature）：从**所有**老文案，批量多选。
- **流B · 批量挖精华**（素材→原料库 + 打法→打法库）：**只从爆款**。
- **纪律**：批量 = 前端**逐条**喂 AI（每条独立 prompt），带进度。
- 候选进**暂存表** `media_mine_candidate`（跨刷新不丢/不白花钱）→ 复核页**去重分组**（同句合并显"出现 N 次"）→ 复选**批量采纳**。
- 老文案列表**已挖标识** `记忆点✓`/`精华✓`，已挖默认跳过（可强制重挖）。

## 关键设计决策（贯穿始终的"宪法"）

1. **AI 注意力纪律（项目核心）**：任何往 prompt 堆信息的设计先过这关。"档案柜不是会议桌"——库只把**当前用得上的那一条**拿到桌上，绝不整库喂干活 AI。整库只能出现在**隔离的匹配调用**或**给人看的 UI** 里。
2. **人拍板**：AI 只提候选，绝不自动写库；人 adopt 才入。诚实不编造（只从真实来源挖，evidence 引原文）。
3. **取材范围按方法论分**：打法/素材**只从真爆款**抽（不爆的是噪音）；口头禅**从所有**老文案抽（腔调不看爆没爆）。
4. **共享边界**：打法库共享（方法论可迁移）；素材/人设独享（是"这个人是谁"）；原料库留 `scope` 接口备将来公司级共享。
5. **能复用别新建**：老文案 + 老视频统一走"反向补录已发内容"；批量挖复用现有 `mine_from_transcript`/`mine_structure`；采纳复用现有落库逻辑。

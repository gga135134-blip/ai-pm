# AI-PM 重新设计执行计划

> 来源：Dieter Rams 审核 15/30，裁决 REDESIGN
> 范围：项目详情页 + 知识库页
> 约束：FastAPI + Jinja2 + Tailwind CSS，中文，手机可用，不引入新框架

---

## 移动端使用场景说明

> 日后手机版可能比桌面版用得更多。本计划的每个 Phase 都必须考虑移动端场景。

**移动端约束（固定）：**
- 使用 `@media (max-width: 767px)` 自定义 CSS（非 Tailwind md: 断点，本地裁剪版不含断点）
- 触摸目标最小 44px 高度
- 无悬浮/hover 状态可依赖
- 横向空间有限（约 360-430px）

**已有移动端基础（不重做）：**
- `base.html`：导航栏已有汉堡菜单（`.nav-mobile-btn` + `.mob-menu`）
- `notes.html`：侧边栏已有折叠切换（`.notes-sidebar-toggle`），动作按钮已有横向滚动（`overflow-x:auto`）

**每个 Phase 需额外考虑的移动端问题：**
- Phase 2（项目详情页）：7层结构在手机上更灾难性，Tab栏需横向滚动，看板6列需要降级方案
- Phase 3（知识库页）：8个按钮在手机上横向溢出，精简到3个是移动端必须而非可选
- Phase 1（颜色系统）：无移动端专属问题

## Phase 1：建立颜色系统（基础层）
> 解决 #3美观(1分) + #5克制(1分)

### 目标
从 5 种无系统 accent 色 → 统一 3 层颜色体系

### 颜色规范

| 角色 | 用途 | 色值 |
|------|------|------|
| 主色 Primary | 主要按钮、链接、活跃Tab | `#2563eb`（蓝-600，已有） |
| AI色 AI Accent | AI专属操作（拆解/执行/作战室） | `#7c3aed`（紫-600，已有） |
| 成功 Success | 完成状态、正面反馈 | `#16a34a`（绿-600） |
| 危险 Danger | 删除、失败、错误 | `#dc2626`（红-600） |
| 警告 Warning | 阻塞、预算预警 | `#d97706`（琥珀-600） |
| 中性 Neutral | 次要按钮、边框、文字 | 灰色系（不变） |

### 废弃的颜色用法
- ❌ 青色 `bg-teal-600`（AI助手按钮）→ 改用 AI紫
- ❌ 靛色 `bg-indigo-600`（AI整理按钮）→ 改用 AI紫
- ❌ 橙色 `bg-orange-500`（周报按钮）→ 改用 中性灰边框

### 修改文件
- `app/templates/base.html`：在 `<style>` 中加 CSS 变量
- `app/templates/notes.html`：按钮行统一颜色
- `app/templates/project_detail.html`：操作按钮统一颜色

### 移动端考量
颜色系统对移动端无专属影响，但统一后减少视觉噪音对小屏幕更有益。

### 验证清单

## Phase 2：重构项目详情页信息架构（核心）
> 解决 #10极简(0分) + #2实用(1分)

### 目标
7 层控制区 → 3 层：Header / Tabs / Content

### 新结构

```
┌─────────────────────────────────────────────────┐
│ ← 项目 / P004 瑶瑶海外站                         │ Layer 1: Breadcrumb
│ 瑶瑶海外站 [active] ⭐2  $0.07  [编辑] [▾更多]    │         + 精简头部
├─────────────────────────────────────────────────┤
│ [看板] [任务树] [资料库(9)] [记录] [🤖 AI指挥]     │ Layer 2: 精简Tab (5个)
├─────────────────────────────────────────────────┤
│                                                 │
│  ┌待处理(1)┐ ┌已完成(10)┐                        │ Layer 3: 内容区
│  │ 任务卡  │ │ 任务卡   │                        │         (看板/任务树)
│  │         │ │ 任务卡   │                        │
│  └─────────┘ └──────────┘                        │
│                                                 │
│  [+ 添加任务]  ← 浮动按钮(FAB)                    │
└─────────────────────────────────────────────────┘
```

### 具体变更

**Layer 1 — 精简头部（合并现有第1-3层）**
- breadcrumb + 项目名 + 状态徽章 + 核心档 + AI费用 → 一行
- 「复制项目」「删除」收入「▾更多」下拉菜单
- AI自动执行状态：仅显示一个小状态指示器（🟢运行中 / ⏸️已停止），点击展开控制面板
- 预算进度条嵌入头部行尾

**Layer 2 — Tab 精简（7→5个）**
| 旧 Tab | → 新 Tab |
|--------|----------|
| 看板 | 看板 |
| 任务树 | 任务树 |
| 资料库(9) | 资料库(9) |
| 决策(1) + 支出(¥0) | 记录 ← 合并，内部子Tab |
| AI作战室 + 项目AI | 🤖 AI指挥 ← 合并，作战室+对话+拆解+执行控制 |

**Layer 3 — 内容区全屏**
- 看板：只显示有任务的列 + 折叠空列（点击展开）
- 任务树：不变，已经简洁
- AI指挥Tab：整合 AI拆解输入 + 手动添加任务 + 作战室 + 项目AI对话

**浮动操作按钮（FAB）**
- 右下角固定「+ 添加任务」按钮
- 展开后显示：手动添加 / AI拆解

### 移动端考量（Phase 2 重点）

**头部（Layer 1）：**
- 手机上 breadcrumb + 项目名 + 所有信息一行放不下
- 移动端头部：`项目名 [状态]` 一行，费用+「▾更多」第二行，单独 `@media` 样式
- 「▾更多」下拉在手机上需要覆盖足够大的区域（min-width 160px，right: 0 对齐）

**Tab 栏（Layer 2）：**
```css
@media (max-width: 767px) {
    .project-tabs { overflow-x: auto; -webkit-overflow-scrolling: touch; flex-wrap: nowrap; }
    .project-tabs button { flex-shrink: 0; white-space: nowrap; }
}
```
Tab 文字可在手机上缩短：「🤖 AI指挥」→「🤖」或保留（用户看得懂）

**看板（Layer 3）：**
- 6列看板横向总宽约 6×280px=1680px，手机上必须横向滚动
- 做法：`.kanban-board { overflow-x: auto; -webkit-overflow-scrolling: touch; }`，列宽固定 `min-width: 220px`
- 不做折叠成纵向列表（失去看板直观感）；横向滚动是看板类工具的普遍移动端方案

**FAB：**
- FAB 已经是移动端友好设计（fixed bottom-right），手机上更重要（替代顶部隐藏的添加入口）
- 手机上 FAB 位置：`bottom: 80px`（避开浏览器底部安全区）

### 修改文件
- `app/templates/project_detail.html`：重写整个模板结构
- `app/api/projects.py`：可能需要新增"记录"合并接口（或前端合并）

### 移动端考量（Phase 3 重点）

**顶部操作区（最大收益）：**
- 旧版 8 个 `flex-shrink-0` 按钮在手机上横向溢出约 600px，需要滚动才能看完
- 新版 3 个按钮（+ 新建▾ / 导入 / ⋯ 更多）在 360px 手机上宽度约 180px，完全不溢出
- 这是 Phase 3 移动端改善最显著的地方

**搜索框：**
- 桌面版搜索框放顶部操作行右侧（`flex: 1`，输入框自适应）
- 移动端搜索框独占一行（`@media` 下换行）：
  ```css
  @media (max-width: 767px) {
      .notes-topbar { flex-wrap: wrap; }
      .notes-search { width: 100%; margin-top: 8px; }
  }
  ```

**下拉菜单：**
- 下拉菜单在手机上需要足够大的触摸目标（`padding: 12px 16px`，行高 min 44px）
- 位置：`position: absolute; right: 0`（确保不超出右侧屏幕边缘）

**IMA 收入侧边栏底部：**
- 手机上侧边栏已折叠（已有 `.notes-sidebar-toggle`），IMA 链接跟着折叠进去——合理
- 或者：IMA 入口同时出现在「⋯ 更多」下拉中（确保手机上可访问）

## Phase 4：补全空状态和交互细节
> 解决 #8细致(1分)

### 空状态设计

| 场景 | 当前 | → 新设计 |
|------|------|----------|
| 看板空列 | 显示 "0" | 折叠列，标题变灰色小标签，点击展开 |
| 知识库无笔记 | 空白 | "还没有笔记，点击 + 新建开始" |
| 项目无任务 | 空看板 | "项目还没有任务。试试 AI 拆解？" + CTA按钮 |
| 搜索无结果 | 空白 | "没找到「xxx」相关内容" |
| AI作战室无worker | 空白 | "当前没有 AI 在执行任务" |

### 交互状态补全

| 状态 | 实现方式 |
|------|----------|
| focus | 所有可交互元素加 `focus:ring-2 focus:ring-blue-500 focus:ring-offset-2` |
| disabled | 按钮加 `opacity-50 cursor-not-allowed` |
| hover | 卡片加 `hover:shadow-md transition-shadow` |
| loading | 按钮内加 spinner + 文字变 "处理中…" |

### 移动端考量（Phase 4）
- 空状态引导文案在手机上不能太长（一行 = 约 18 个汉字）
- focus 环在手机上通常不可见（无键盘），但 iOS 可能触发，不会出错
- disabled 态和 loading 态在手机上同样重要（防止双击）

### 修改文件
- `app/templates/project_detail.html`：看板空列+空项目
- `app/templates/notes.html`：空列表+空搜索
- `app/templates/base.html`：加通用 focus/disabled 样式

### 验证清单
- [ ] 每个空状态都有引导文案
- [ ] Tab 键可以遍历所有按钮并有可见 focus 环
- [ ] loading 状态按钮不可重复点击

## 执行顺序建议

| 阶段 | 估计工作量 | 依赖 |
|------|-----------|------|
| Phase 1：颜色系统 | 1小时 | 无 |
| Phase 2：项目详情页重构 | 3-4小时 | Phase 1 |
| Phase 3：知识库页重构 | 2小时 | Phase 1 |
| Phase 4：空状态+交互 | 1-2小时 | Phase 2, 3 |

**总计约 8-10 小时**，建议分 2-3 个工作会话完成。
